## 1. pds-tool 盘点（1688 采集与转换）

> 详见主文档 `流程方案.md` §1.2。要点回顾：
> - 采集两条路：1688 开放平台 API（需企业资质申请 App Key/Secret/Token，签名=参数升序+MD5）；无凭证时降级页面解析（httpx + 正则提取 `window.__INIT_DATA__`，仅单 offer 导入，搜索无兜底）。
> - 转换规则（最值得抄）：标题去噪（剔除"厂家直销/一手货源/批发价/一件代发/包邮"等词 + `【】[]` 内容）、加价策略（`售价=源价×倍率` 默认 1.3，>10 元取整 −0.1）、类目关键词映射、描述 HTML 生成带 XSS 清理。
> - 铺货执行：任务筛选（状态/类目/关键词/标签）→ 转换 → 推送（Shopify/PDD/抖音/快手/通用 HTTP/CSV），APScheduler Cron。
> - 局限：无闲鱼目标平台；采集走官方 API 非登录态；1688 采集执行器需自建（httpx 非登录解析）。

## 2. FishClaw_MCP 盘点

> 路径：`reference/fishclaw-mcp`。依赖：mcp[cli]>=1.0.0、playwright>=1.58、playwright-stealth、openai>=2.24。
> **定性：Playwright 浏览器 RPA + MCP 壳**，不调闲鱼私有 HTTP 接口、无签名，凭真实浏览器会话 Cookie 通行。

### 2.1 MCP 结构（server.py）
- FastMCP 建服务，12 个 tool：闲鱼侧 `login/search_market/draft_item/publish_item/get_selling_items/manage_item/get_page_content/restart_browser/simulate_farming`；生成侧 `generate_image/generate_image_prompt/generate_product_description`。
- 传输：默认 stdio；`--http` 走 streamable-http 于 `http://localhost:8000/mcp`，无鉴权。
- 工程范本：同步 Playwright 经 `_run_sync`（server.py:92-98）投到 `max_workers=1` ThreadPoolExecutor（server.py:89），懒加载单例（102-130）——**FastAPI 里跑 Playwright 的标准写法，可直接照搬**。

### 2.2 核心逻辑（tools/xianyu_tools.py）
- 无 URL/API/签名——全 DOM 操作。Cookie=真实浏览器会话，JSON 落盘（`_save_cookies`/`_load_cookies`），登录拦截器 `_ensure_logged_in` → 扫码登录 `_do_qrcode_login` 等真人扫码。
- 发布流程（draft_item 子步骤，均可复用）：`_prepare_image`(URL 下载/本地校验) → `_upload_image`(file input 注入) → `_fill_text_field`(先填触发词自动归类再替换真描述) → `_select_category` → `_fill_price`(逐字键入) → 截图。
- 采集：`search_market` 搜索页 `page.evaluate` 抓卡片（CSS class 子串，易碎）；`get_selling_items` 跳个人页滚动 + JS 去重采集。
- 能力缺口（**无**）：订单查询、自动发货、站内消息收发/AI 回复、改价/编辑/重新上架、多账号。

### 2.3 生成工具（可直接 import 复用）
- generate_image_tools.py：阿里云 DashScope 文生图（z-image-turbo），Bearer key，产物=商品封面图，失败回退默认图。
- prompt_tools.py：OpenAI 兼容 SDK 调 DashScope compatible-mode（默认 qwen-max），生成生图 prompt / 闲鱼三段式商品文案，system prompt 可 env 覆盖。

### 2.4 对我们的结论
- 定位 = "人肉模拟" RPA 层，不能高并发；接自建系统最省事的方式 = 把 `FishClawTools` 当普通类 import 进 FastAPI 后台任务，套用单线程 executor 模式（跳过 MCP 壳）。
- 发布/下架/在售采集的 Playwright 套路 + 登录保活 + 封面图/文案生成可直接复用；订单、发货、消息、自动回复需自建（走 goofish-cli 的接口知识，见下）。

## 3. goofish-cli 盘点（★ 接口知识最密集）

> 路径：`reference/goofish-cli`。版本 0.3.0，Apache-2.0。Single Registry → CLI/MCP 双形态共享命令。
> **定性：纯 mtop HTTP 客户端 + IM WebSocket 通道 + 浏览器兜底**，逆向协议文档化程度最高。

### 3.1 发布商品（commands/item/publish.py）★★★
- 发布链路四步：逐图 upload → `category.recommend(title, images)` AI 类目 → `location.default()` 地址 → `mtop.idle.pc.idleitem.publish` v1.0。
- **发布请求体 DTO（自建最该抄）**：`imageInfoDOList`（url/isQrCode/size/major/type/status）、`itemTextDTO`(desc/title/titleDescSeparate)、`itemPriceDTO`(priceInCent=元×100 转 str、origPriceInCent)、`itemPostFeeDTO`（包邮/按距离/一口价/无需邮寄四态）、`itemAddrDTO`、`itemCatDTO`(catId/catName/channelCatId/tbCatId)、常量 `itemTypeStr:"b"`、`quantity:"1"`、`publishScene:"pcMainPublish"`、硬编码 `uniqueCode:"1775897582791680"`。
- 类目推荐：`mtop.taobao.idle.kgraph.property.recommend` v2.0，取 `categoryPredictResult` 的 catId/catName/channelCatId/tbCatId/confidence。
- 默认地址：`mtop.taobao.idle.local.poi.get` v1.0，`data.commonAddresses[]`。

### 3.2 图片上传（commands/media/upload.py）★★★
- `https://stream-upload.goofish.com/api/upload.api`，非 mtop、无签名；cookie 会话 + multipart `file` 字段；query `floderId=0&appkey=xy_chat&_input_charset=utf-8`；一律声明 `image/png`；返回 `object.{url, pix:"WxH", size}`。只支持图片。

### 3.3 登录态（core/session.py、commands/auth/login.py）★★★
- Cookie 存 `~/.goofish-cli/cookies.json`，Fernet 加密（密钥=hostname+username+盐 PBKDF2-480k，**跨机不可迁移**）；判据：`unb` + `_m_h5_tk`；三件套 `unb/_m_h5_tk/cookie2`。
- 5 条获取路径：浏览器 cookie 自动探测（browser_cookie3，Chrome/Edge 等）→ 指定浏览器 → 导入文件 → 粘贴 raw → `--qr` Playwright 扫码。
- 自动续命（core/refresh.py）：`_m_h5_tk` 约 10 分钟效期；遇到 `FAIL_SYS_TOKEN_EXOIRED`（服务端真实拼写）/`FAIL_SYS_SESSION_EXPIRED` 时 Playwright 点"快速进入"免密按钮刷新。`FAIL_SYS_ILLEGAL_ACCESS`（风控）不可自动救。
- device.json（device_id 按 unb 缓存）、im_token.json（IM token，TTL 30min，appKey `444e9908a51d1cb236a27862abc769c9`）。

### 3.4 签名算法（core/sign.py + static/goofish_js_version_2.js）★★★
- 端点：`https://h5api.m.goofish.com/h5/{api}/{version}/`，POST 表单 `data=<紧凑 JSON>`。
- 签名：`sign = md5(token + "&" + t + "&" + appKey(34839810) + "&" + data)`，token=`_m_h5_tk` 中 `_` 前部分，t=**真实毫秒**（`int(time.time()*1000)`），data=`json.dumps(data, separators=(",",":"))`。无 salt、无二次混淆。
- query 参数：jsv=2.7.2、appKey=34839810、t、sign、v、type=originaljson、accountSite=xianyu、dataType=json、sessionOption=AutoLoginOnly。
- 错误分类：RGV587/哎哟喂 → 风控；SESSION_EXPIRED/TOKEN_EXOIRED → 可自动恢复；ILLEGAL_ACCESS → 不可恢复；限流 1 写/分钟令牌桶 + RGV587 熔断 10 分钟。

### 3.5 IM 消息通道（★ 全走 WebSocket，HTTP 无 IM）
- WS：`wss://wss-goofish.dingtalk.com/`，鉴权帧 /reg（app-key/token/ua/did/mid）。
- 读会话：`mtop.taobao.idlemessage.pc.session.sync` v3.0（Top N 会话，sessionType 1真人/3系统/6互动/23通知）。
- 读消息：WS `list_user_messages`（body `[cid@goofish, False, 9007199254740991, limit, False]`，消息体在 `custom.data` base64 JSON）。
- 发消息：WS `sendByReceiverScope`（contentType:101 + custom data base64），支持文本/图片；无会话时先 create_chat。
- 实时收：watch 常驻，心跳 `/!` 15s、每 600s refresh_login、断线指数退避；推送三类：message/read/new_msg（new_msg 只有指针需拉正文）；解码链路：明文 JSON → base64(JSON) → JS decrypt(base64+msgpack)。
- **AI 回复不在项目里**：watch 只出事件流，回复策略在 skills/goofish-reply-buyer（意图 5 分类 → 起草 → **用户确认后才发**）。

### 3.6 查询接口（采集参考）
- 商品详情：`mtop.taobao.idle.pc.detail` v1.0（itemId），富字段在 `data.itemDO/sellerDO/itemLabelExtList`（含 seller replyRatio24h/replyInterval——判断卖家活跃度）。
- 在售列表：`mtop.idle.web.xyh.item.list` v1.0（userId=unb、pageNumber、pageSize 20），cardList[].cardData。
- 搜索：无公开 API，浏览器 DOM 抓取（易碎，仅应急）。

### 3.7 Skills 资产（纯知识，可直接搬运）
- publish-item：标题 5 段式 `[品牌][核心词][关键属性][场景/情感词]`，≤30 字最优 18-28；描述 200-400 字含成色/瑕疵主动披露（防仅退款）；图 ≤9 张首图 1:1 ≥3 张；发布后 24h 内不频繁编辑（流量池窗口）。
- reply-buyer：意图 5 分类（询价/议价/催付/售后/外联）交 LLM；议价三档阶梯（小刀 5-15% 接/大刀 15-40% 中间价/屠龙刀 >40% 拒）；口吻人设；**永不自动发消息原则**。
- risk-guard：发布前扫 blockers/warnings/suggestions；10 条发布红线（改价+改标题=虚假促销、复活下架品=二次下架标记、新号日>10 件限流等）；x5sec 恢复 SOP（人工浏览 3-5 分钟触发下发 → 重导 cookie → 仍失败停 2-6 小时）。

### 3.8 对我们的结论
- **接口层照抄**：发布 DTO、上传流程、签名算法、错误分类、限流/熔断框架、WS 协议解码链。
- **规则库照搬**：质检/议价/风控/标题公式 = 纯提示词资产，与代码零耦合。
- 坑：路径硬编码 `~/.goofish-cli/`、cookie 机器绑定不可迁移、mtop 接口随前端改版、IM token 接口风控敏感需缓存、media 一律声明 image/png。

## 4. xianyu-pilot（旧版）盘点

> 路径：`reference/xianyu-pilot`。全栈 Docker Compose 单机部署：FastAPI(Python3.11) + Vue3 + MySQL8 + Redis + 独立 worker + Node Playwright crawler。
> **注意：该项目已停止维护，能力已迁移至 xianyu-pilot-pro（见 §5）。此处盘点价值 = 高质量的单体参考实现。**
> 缩写：`S=`apps/api/app/services，`C=`apps/api/app/core，`M=`apps/api/app/models。

### 4.1 登录态 ★4
- **扫码登录**（C/xianyu_qr_login.py，进程内存 `_sessions` dict）：三阶段取 Cookie——`_get_m_h5_tk`（两次 POST h5api 触发 Set-Cookie）→ `_get_login_params`（GET passport.goofish.com mini_login.htm 正则取 umidTag）→ `_generate_qrcode`。状态机 `new/scaned/confirmed/expired/cancelled/verification_required`；路由 `POST /api/qrlogin/generate`、`/status/{id}`、`GET|POST /cookies/{id}`。
- **加密存储**（C/cookie_crypto.py）：`enc:v1:{b64(iv)}:{b64(ct+tag)}` = AES-256-GCM，密钥 SHA256(COOKIE_CRYPTO_SECRET)。三表存储：`XianyuAccount`(external_uid=unb)、`XianyuAccountAuth`(encrypted_cookie/encrypted_token=_m_h5_tk/cookie_status)、`XianyuAccountRuntime`(ws_status/心跳)。
- **自动刷新**（S/cookie_token_refresher.py）：单 dispatcher 60s tick，每账号独立锁 + 三套随机间隔——Cookie 保活 30min（hasLogin.do）、_m_h5_tk 1.5–2.5h、WS accessToken 10–14h；回写重加密 + 直改 ws_client 内存凭据；失败码 CAPTCHA_NEEDED/SESSION_EXPIRED → cookie_status=0 + 通知。
- **坑**：扫码会话进程内存（多 worker 漂移）；大量裸 SQL + f-string 拼表名；`window.viewData` 正则易碎；单密钥无版本轮换。

### 4.2 消息通道（WS 长连接 + 增量长轮询）★3
- `WS_URL="wss://wss-goofish.dingtalk.com/"`，心跳 15s、重连 5s；每账号一个 `XianyuWebSocketClient`，`WebSocketManager` 管多实例。
- **协议**（S/ws_protocol.py）：/reg 鉴权帧（app-key `444e9908a51d1cb236a27862abc769c9`、token、did=UUID-UNB）；增量同步=`/r/SyncStatus/ackDiff`（pts 游标长轮询）；ACK=`/!`（pnmId, code 200）；发文本/图片=`/r/MessageSend/sendByReceiverScope`（body 内 contentType:101 + custom base64，**actualReceivers 必须含发送者自己否则 code=500**）。
- 收包分发：`/s/para /s/sync /s/vulcan /r/SyncStatus/ackDiff` → parse_sync_package → 先 ACK 再处理。
- **可靠扇出（最值得抄）**（S/message_automation_outbox.py）：每条新消息**同一事务**写 `message_automation_outbox` 双分支（delivery/ai）；worker `SELECT…FOR UPDATE SKIP LOCKED` + lease 300s + 指数退避 + retry_safe 语义。
- 消息持久化：S/ws_storage.py（MySQL，非 redis！按 pnm_id 幂等 upsert）。推前端：SSE（/sse/ticket 一次性票据）。
- **坑**：协议全是阿里私有逆向（URL/app-key/字段），改版即失效；SSE broadcaster 进程内，多副本漏事件。

### 4.3 闲鱼 API 封装 ★3
- S/xianyu_api_service.py（1090 行）函数清单：
  - 订单：`mtop.taobao.idle.trade.merchant.sold.get`（sold orders）、`mtop.taobao.idle.merchant.refund.list`（退款）。
  - 发货：`mtop.taobao.idle.logistic.consign.dummy`（确认发货）、`mtop.idle.groupon.activity.seller.freeshipping`（免邮）。
  - 会话用户：`mtop.taobao.idlemessage.pc.user.query`。
- **签名**：`MD5(f"{token}&{t_ms}&{APP_KEY}&{data_str}")`，APP_KEY=`34839810`，data_str=`json.dumps(data, separators=(",",":"))` **字段序敏感**；H5_API_BASE=`https://h5api.m.goofish.com/h5`，query 带 jsv/appKey/t/sign/type=originaljson/sessionOption=AutoLoginOnly。
- token 机制：_m_h5_tk 需**空 token 探活**触发 Set-Cookie；过期码 `FAIL_SYS_TOKEN_EXOIRED`（服务端真实拼写）时从 Set-Cookie 提新值重试一次。
- **坑**：签名/UA 复制 5 份；风控识别靠 RGV587/滑块文案子串匹配。

### 4.4 自动发货 ★4（★事件触发+状态机最干净）
- **触发不走 HTTP 轮询，全走 WS 消息**（S/ws_delivery_handler.py）：`is_payment_message`（reminder 命中"等待你发货/买家已付款"正关键词，排除"待付款"负向）→ 付款即发货；小刀砍价成功后发货；从消息卡片 URL 抠订单号。节流：同 account+pnm_id 60s 一次（防 WS 周期性付款推送重复发货）。
- 规则（S/realtime_delivery.py 状态机）：`DeliveryRule`（delivery_mode: kami/text/card/custom/api、trigger_on_pay、trigger_keyword、max_delivery_per_day）+ SKU 级覆盖；卡密从 CardItem 取，孤儿回滚 heal。
- 发送：多段 text/image 逐条 0.5s 间隔（**禁止合并成一条**）；图片须已是闲鱼图床 URL。
- **两阶段语义**：①WS 发消息成功=message_confirmed；②如 auto_confirm_shipment=1 再调 confirm_shipment mtop → platform_confirmed/success；**"消息发出但结果未知"一律不自动重发**（_ALREADY_SENT_STATES：success/unknown/message_sent…），只提示人工核对——防重发哲学很值得抄。
- 兜底恢复（S/delivery_recovery.py）：worker 每 600s 扫未发货订单（order_status 1/2、pay_time 超 300s、delivery 配置开启）补发；>24h 死信复活。
- 手动通道（S/manual_delivery.py）：ManualDeliveryCoordinator + unique(order_id)+unique(idempotency_key) 双幂等，与实时共用底层发送接口。
- **坑**：付款消息关键词硬编码（闲鱼文案一变发货即哑）；卡密库存强耦合 CardItem。

### 4.5 AI 自动回复 ★4
- 触发链：WS 新消息 → outbox ai 分支 → `_should_trigger_ai_auto_reply`（direction==IN、排除卖家回显=AI 回环防护）→ batcher。
- **批处理器**（S/ai_reply_batcher.py）：按会话攒批，8s 静默期合并调一次 AI；双去重（pnm 指纹 15min + 语义指纹 90s）；批量上限 20 条/批 12000 字，budget 新→旧分配。
- **Scope 三级开关（前置）+ policy 判定（后置）**：`_check_auto_reply_scope` → 全局 enabled → 账号级 scopes → 商品级 `auto_reply_enabled`（**NULL=继承账号全局 / 0=强制关 / 1=强制开**）→ 关键词自动回复（命中先回，不耗 AI）→ 迟到消息抑制（AI 已回后买家旧消息不再触发）→ `evaluate_ai_auto_reply_policy`。
- **准入策略**（S/ai_auto_reply_policy.py，frozen dataclass `AiAutoReplyPolicyDecision`，纯函数可单测）：判定序 = timeZone(仅上海/UTC) → maxDailyReplies(默认 200) → mode(auto/hybrid/manual) → workHours24 → pauseOnHumanIntervene(30min) → safeMode → 关键词闸(handoff 人工接管/blacklist) → workStart/End(左闭右开跨午夜)。buyer 重复消息**不是 policy 项**（去重靠 batcher + claim 单飞）。
- **AiAutoReplyCommand 字段**：event_key/request_digest/source_message_digest（sha256 hex64）/account_id/session_id/peer_id/goods_id/seller_external_uid/quota_date/quota_limit/policy_timezone（无昵称/消息原文，内容另行携带）。
- **LLM 接入**（S/ai_provider.py）：OpenAI 兼容，无 openai SDK（httpx 手写 /v1/chat/completions，`request_public_https`，请求 512KB/响应 1MB）；模型配置 DB 存或 env（默认 gpt-4o-mini），缓存 TTL 60s；**generate_text 不抛异常只返 ok:false**。
- **提示词拼装**（automation_runtime._build_system_prompt）：systemPrompt(截 6000) + 商品事实(截 4000) + 知识库 + 聊天规则 + 人设 + 尾约束"不得编造"；历史 _load_history_messages。
- **发送边界语义（重要）**：attempt 状态集 pending/generating/message_sending/message_sent/confirmed/failed/unknown；`message_sending` 先提交本地再外发；**unknown 永不自动重发（quarantine），重试只对生成失败安全**；confirmed = 平台 ACK + 本地落库；**无"草稿待人工确认"态**（manual mode 在 policy 直接拒生成）。
- **配额原子性**：`_reserve_quota`（occupied_count<quota_limit 原子 +1，超限抛 AiAutoReplyQuotaExceeded）→ 确认后 `_consume_quota` / 失败 `_release_quota_reservation`（occupied-1, released+1）。
- **坑**：batcher 进程内存（多 worker 需换 redis）；时区用部署本地 naive 时间（混 UTC 会让 lease 长 8 小时）；"人工 OUT 30 分钟接管"依赖 pnm_id 前缀约定；多实例跨 worker 去重靠 DB claim（event_key 单飞），勿依赖 batcher 内存。

## 5. xianyu-pilot-pro 盘点

> 路径：`reference/xianyu-pilot-pro`（zip 快照 main `4ac92222`）。**这是旧版 xianyu-pilot 的继任者（已全面开源）**，SaaS 形态。

### 5.1 服务分工（三服务 + 双向纯 HTTP）
- **core-api（Java/Spring Boot）**：主数据 + 租户 + 管理网关 + 计费收口。账号/Cookie 主数据（`C/service/XianyuAccountService`）、规则/货源/工作流 CRUD、会员计费支付、AI 计价。

### 5.7 数据库 schema（★ 自建最佳参考，最重要）
- 物理：MySQL `xianyu_assistant_admin`（core+automation 同库双 owner）+ PG `xianyu_crawler`。**core 不用 Flyway**：SchemaCompatibilityRunner.java 启动幂等建表（14 个 ensure* ~90 张 CREATE TABLE IF NOT EXISTS + information_schema 探测后 ALTER）；automation 用 SQLAlchemy create_all + ensure_runtime_schema_compatibility。
- 通用约定：id BIGINT AUTO_INCREMENT；tenant_id（NULL=全局）；**软删 deleted TINYINT NOT NULL DEFAULT 0 且进唯一键 uk(tenant,业务键,deleted)**；**外部大整数一律 VARCHAR(64-200)**（orderId 超 bigint 被静默写 NULL 致重复发货——V1.35 修）；金额分层（交易 DECIMAL(18,4)/AI 单价 DECIMAL(18,8)/抽佣 DECIMAL(5,4)）；collation 全库统一（混用 JOIN 报 1267）。
- **核心表**（表｜owner｜关键字段）：
  - 账号：xianyu_account/_auth/_runtime/_health_snapshot/_membership（5 表家族）
  - 商品：xianyu_goods（JSON 快照 image_urls/raw_payload + auto_relist_* 6 字段）+ property/_value/_sku/_edit_snapshot（sku property_key VARCHAR(512) + uk(external_goods_id,property_key)）
  - 订单：xianyu_trade_order + _item（双 VARCHAR ID）；refund/rate 三件套（记录表+同步任务表+账号状态表 is_syncing）
  - 消息/AI：xianyu_chat_message（pnm_id/message_uid 幂等 + 复合索引）/xianyu_conversation（会话暂停状态列）/xianyu_message（兼容汇总）/auto_reply_rule（三层 scope）/auto_reply_log/quick_reply_template/default_reply/message_filter/ai_cs_session/_message/_knowledge/_kb_category(三级 name_hash)/_learned_kb(content_hash)/user_business_setting((tenant,user,setting_key) 唯一)
  - AI 计价：ai_model_price_config（billing_mode token|per_call|spec）/ai_model_tier_price/ai_usage_log(request_id 唯一)/token_balance_ledger/**admin_module_record**（泛 KV：模型配置+feature_switch）
  - 发货：delivery_rule/delivery_goods_config/delivery_statement_session/delivery_template/delivery_text_source(segments JSON)/delivery_record(delivery_mode+status 双状态)/card_group（total/used/remain/available 四冗余计数）/card_item（原子认领索引）/delivery_block_rule
  - 调度/工作流：scheduled_task（lease 三件套）/workflow 12 表（workflow_definition/_node/_edge/_execution/_artifact/_timeline/_checkpoint/workflow_goods_draft/workflow_published_goods 双唯一）
  - 滑块：xianyu_captcha_solve_record（23 列状态机）/captcha_solve_attempt（实验变量）/captcha_backoff（PK=account_id）
  - 系统：sys_user（token_balance/vip_level/security_version）/billing_plan/payment_*/notification/user_business_setting/china_address_dict（adcode=闲鱼字段）
- **自建建议**：单语言单套版本化迁移；外部 ID 全字符串；软删/租户/唯一键统一；AI 用 OpenAI 兼容薄客户端 + DB 泛 KV 模型配置（admin_module_record 模式）兼容 DeepSeek/通义。

### 5.9 可直接借鉴清单（自建优先级）
1. **数据库 schema**（5.7 全部）：账号 5 表、商品 JSON 快照、订单双字符串 ID、发货幂等索引、scheduled_task lease 三件套 ★5
2. **发布流程**：三步发布（类目→CDN 图床→构造）+ 草稿状态机 + 发布去重表 + 快照溯源链式重发 ★4
3. **决策流水线**：消息落地 → DB 决策状态机 → 发送成功再计费（request_id 幂等 + pending 补扣）★5
4. **会话级 auto_reply_state 状态机**（人工暂停/恢复/禁用，跨重启）★4
5. **AI 泛 KV 模型配置**（admin_module_record 模式，任意 OpenAI 兼容端点）★4

### 5.10 坑（自建要绕开）
- Java/Python 混合 + 双套迁移机制维护同库——**我们单 Python 单套迁移即可规避**；
- MySQL 无 `ADD COLUMN IF NOT EXISTS`，必须"探测→拼 DDL→执行"；
- 外部大整数必须字符串化（否则静默 NULL 致重复发货）；
- 多层软删坑（已消费≠软删、deleted 默认漂移、软删后重建唯一键冲突）；
- 注释与实现漂移严重（多处自陈"文档性质实际由 runner 执行"）；
- 商业版残留多（会员/Token/分销/广告/卖滑块 API 纠缠核心逻辑），自建只取核心骨架。
