## 0. 结论速览

1. 全新部分只有两块：**自然语言入口**（~~MCP + Skill~~ → **后端 pipeline + 前端输入框**，见 D-2026-09-19-14 修正注）和**本地文件夹工作区**。采集、发布、定时上架、手动触发四段**存量已实现**。
2. **手动触发不用新建**：`POST /goods/collect-1688`（`api/routes/goods.py:166`）+ `Collect1688View.vue:83`「开始采集」已覆盖采集；`POST /goods/{id}/publish`（`goods.py:117`）+ `GoodsView.vue` 行内「上架」（带二次确认弹窗）已覆盖单件发布。**只缺"批量放行"**。
3. **定时只缺采集半边**：`auto_listing` 任务已注册在跑（`scheduler/task_runner.py:33-37`，600s 扫 `MAPPED`）；`collect_1688` 任务类型不存在，`cron_expression` 字段已有但是占位（`task_runner.py:11,276`）。
4. 定价采用**三级降级链**：1688 成本价可用 → LLM 定价（带证据与置信度）→ 不可用/越界 → **人工定价**。明确一条事实：**1688 详情页价格是成本价，不是市场价**，它能约束价格下限，定不出"能卖多贵"。
5. 定时链路形态为**半自动**：定时任务跑「采集 → LLM 定价 → 文案 → 风险扫描 → 待确认清单」，**绝不自动发布**；人工批量放行后，才由已有的 `auto_listing` 发出去。
6. 上线前必须先修 §9 的 3 个存量缺陷，否则链路第一步就断（`source_offer_id` 缺列会直接报错）。
7. **虚拟商品与自动发货：执行侧 100% 存量可用**（`publisher.py:205,262` 的 `virtual` 分支、`fulfillment/delivery.py` 整条付款→发货链、`CardGroup.goods_id` 绑定、`DeliveryRule` 四类内容、幂等记录与转人工兜底）。**增量只有一个**：让大模型生成虚拟商品文案 + 创建发货配置，不要重写发货。
8. 触发与可视化形态定为**流程面板**（步骤条 + 每步状态/耗时/日志/可中断），**不是前端聊天框**——后者要推翻 D-2 自建 agent 循环，成本高且与已定架构冲突（§8.4）。
9. 所有"避免 LLM 操作报错后加重风险"的约束（熔断、失败分类禁重试、节奏、互斥、幂等）统一收在 `docs/闲鱼风控操作手册.md §4` 的 R-1～R-10，本文只引用不重述。

`decision.pricing` 四值：`llm`（成本价可用且模型在护栏内出价）/ `fallback-rule`（回落 `markup_price` 1.3，待人工复核）/ `manual`（拿不到成本价，或模型判"偏好与护栏区间冲突"→ 价格留空，**必须人工填**）/ `human`（**不是模型可输出的值**，由 `edit_offer` 人工填价后置上，视同已确认价；放行闸门只拦 `manual` 与空价，故 `human` 可放行）。

```
sourced → decided（= 待确认，定时链路到此为止）→ confirmed → imported(MAPPED)

### 3.3 硬性规则

1. **`collect` 段只由采集器写**，LLM 永不可改（原始证据不被污染）；
2. **`decision` 由 LLM 写一次**，人工放行时只追加 `confirmed_by/confirmed_at`，改写要重新走确认；
3. 重采同一 offer：`collect` 更新、`decision` 保留；要改已确认决策 → 复制到新 `batch_id`，不原地改；
4. `data/collect/` 整体进 `.gitignore`，只提交 schema 与 fixture。

**边界（三条铁律）**：

1. 大模型**只产 `decision`，不产发布动作**；`import_to_pool` 之后的事全归存量。
2. **触达闲鱼平台的写出口只有一个**：`listing/publisher.py:242 publish_goods`。它的调用方仅两处——人工放行进入 `MAPPED` 后由存量 `auto_listing` 轮询发出，以及带 `confirm_token` 的 `publish_goods_now`。其余写类工具（`import_to_pool`、`create_virtual_goods`、`configure_auto_delivery`）**只写本地工作区或自家 DB，不产生任何平台请求**。**禁止大模型或定时任务绕过上述两处直接打闲鱼。**
3. ~~MCP 工具与 REST 路由调用同一批 service 函数~~ → **定时 handler、`/api/collect/run`、`/api/goods/collect-1688` 调用同一批 service 函数**，不允许某个入口里另写一套业务逻辑。这条铁律**没有因为 MCP 作废而失效，反而更要紧**：现在同一条链路真有三个入口在跑，参数还共用同一个 pydantic 模型（`CollectRunRequest`），就是为了不让"端点跑得过、定时跑不过"那种分叉长出来。

**半自动边界（本版核心约束）**：第 ⑤⑥⑦ 步需要人参与。定时任务与 `/api/collect/run` 都只能执行到 ①–④，产出待确认清单即停，**不得进入 ⑤ 之后**。

## 7. 定价与文案设计

### 7.1 三级降级链（R4）

```
[1] 成本价可用（collect.source_price_cent > 0 且 price_available=true）
      ↓ 是 → LLM 定价：输出 price_cent + reasoning + confidence
      ↓ 结果越界 [成本×1.15, 成本×3.0] / 解析失败 / 无 reasoning
    [2] 规则兜底：transform.markup_price(成本, 1.3) → decision.pricing="fallback-rule"（标黄待复核）
    [3] 成本价拿不到 → decision.price_cent=null，pricing="manual"（标红，必须人工填）
```

**关键事实（务必对用户诚实；~~也写进 Skill~~ 这条现在落在代码与页面上，不靠提示词）**：1688 详情页价格是**成本价/批发价**，只能约束下限；不知道闲鱼市场价时，LLM 出价本质是"成本 × 常识倍率"，不是市场定价。所以 `confidence` 上限锁 `medium`（**代码夹住**：`decision.py:222` 把模型给的 `high` 一律降成 `medium`；提示词第 9 条同时声明"你没有市场数据"——两道而不是一道），除非有竞品数据。

### 7.2 结构化输出前置改造

`ai/provider.py:38` 现在只收 `messages/temperature/max_tokens`，返回纯文本。新增 `ai/structured.py`：

```
async def chat_json(system: str, user: str, schema: type[BaseModel], *, retries=1) -> BaseModel
```

- 带 `response_format={"type":"json_object"}`；不支持的 base_url（部分 Ollama/自建）降级为"提示词要求 JSON + 剥 ```json 围栏"宽容解析；
- 失败 → 追加一轮"只回 JSON"修正 → 再失败**抛错，不猜**；
- pydantic 即硬边界：`price_cent` 必须 `int`、`∈[100, 1000000]`、`evidence` 非空。

### 7.3 定价提示词（可直接用）

**System**

```
你是闲鱼二手/无货源店铺的定价助手。你的任务：给定一件从 1688 采集到的商品的
**采购成本价**，给出一个适合挂在闲鱼的售价、划线原价，以及是否包邮。

必须遵守：
1. 你拿到的价格单位是「分」，输出也必须是「分」的整数。
2. 成本价是进货价，不是市场价。你无法得知市场行情，因此禁止表现出"市场价就是这样"的确定语气。
3. 售价必须落在 [成本×1.15, 成本×3.0] 区间内。超出即视为无效，改判 pricing="manual"。
   理由：下限覆盖运费+包装+售后准备；上限避免价格离谱到无人问津或被判定恶意抬价。
4. 常见倍率参考（不是硬规则，需在 reasoning 里说明为何偏离）：
   - 低值易耗/高同质化（数据线、手机壳、袜子）：2.5–4.0 倍
   - 中值日用（小家电、收纳、厨具）：1.8–2.8 倍
   - 高值/强规格（家具、器械、大件）：1.3–1.8 倍
5. 尾数定价：>10 元用 x.9 / x.90（如 1990 分 = 19.9 元）；≤10 元保留到分。
6. 划线原价（orig_price_cent）必须 > 售价，且 ≤ 成本×5；填不出来就置 null。
   这是"折扣感"字段，禁止编造一个不存在的更高历史价。
7. delivery 只能取："包邮" / "按距离计费" / "一口价" / "无需邮寄"。
   成本价里已含邮费、或商品轻小 → 倾向"包邮"；大件/高运费 → "无需邮寄"。
8. 若用户给了目标价或加价偏好，优先尊重，但仍受第 3 条硬区间约束；
   冲突时不要折中，直接 pricing="manual" 并在 reasoning 说明冲突原因。
9. confidence 最多给 "medium"（你没有市场数据）；只有当输入里出现竞品在售价格样本时才可给 "high"。

只输出 JSON，不要任何解释文字、不要 markdown 围栏。
```

### 7.4 文案提示词要点

`clean_title`（`transform.py:20`，14 个营销词去噪）**只是喂给模型的打底材料**（`_copy_user_prompt` 里那行"去噪打底标题"）→ 模型基于 `collect.specs` 生成 **3 版标题候选 + 1 版描述**。
**成品文案只出自模型**（2026-09-20 修正，此前失败会回落 `clean_title(title_raw)`）：模型不可用时 `title`/`desc` 留空、`copy_source="none"`、`copy_error` 记下原因，由 §7.4 末尾的 `run_risk_scan` 以 `title_missing`/`desc_missing` 拦在放行之前的待确认清单里（面板标「文案空白」），出路只有两条——重跑，或 `PATCH /api/goods/{id}` 人工改写（人工改过的行 `copy_source` 置 `human`，口径同 `pricing=human`）。
> 为什么原来那条兜底必须拆掉：1688 源标题动辄 >30 字且带「超级/爆款」，去噪版落进 decision 必撞 `title_too_long`；而该 code 在 `risk_scan.NOT_COPY_FIXABLE`（判定"重跑文案救不了"）里 → 节点 4 的改写循环永不触发。结果是 2026-09-19 那批 2 件全部以「风险扫描未过」卡死在闸门前，用户点批量放行一件也选不上，而界面看起来像"文案早就写好了"——**拿上游文案冒充成品，既不是"改写"，又制造假成功**。
System 约束：只描述输入里真实存在的规格事实；禁绝对化词（最/第一/唯一/完美）、禁站外链接与联系方式、禁虚构使用经历、禁货源话术（代发/厂家直销/批发）；标题 ≤ 30 字且含核心规格；描述分段：成色与规格 / 适合场景 / 发货与售后。
之后必须过 `run_risk_scan`，清单搬 `goofish-risk-guard`（绝对化词、类目偏差、降价改标、9 图合规、外联词、误导承诺）。

#### 虚拟商品文案专用约束（叠加在 §7.4 之上）

- **禁邮寄话术**：不出现"发货/物流/快递/包装"，统一用"拍下后自动发送 / 秒发 / 在线发送"；
- **必须写清三件事**：交付形式（卡密 / 网盘链接 / 文本 / 兑换码）、使用方式与有效期、非实物不支持无理由退换的边界；
- **站外链接要分两类判，不要一刀切**：品类 A 的交付物本身就是网盘/发卡链接，属正当需求；该禁的是**引导脱离平台交易**的话术（加微信/QQ、私聊站外付款）。`run_risk_scan` 需把这两类拆成 `external_link_delivery`（放行）与 `off_platform_deal`（拦截），否则 §7.4 的"禁站外链接"会把虚拟商品全判违规；
- **一票否决品类**（提示词与扫描双层拦）：盗版资源、影视/会员账号代登、外挂破解、虚拟币与代充、证件与代考、他人付费内容原样转卖；
- 借用 `ai-goofish-monitor` 的 criteria 写法（`prompts/macbook_criteria.txt`）：一票否决项显式列出 + **信息缺失标 `NEEDS_MANUAL_CHECK` 而非直接否决**；其"图文冲突以图为准"对虚拟商品封面同样适用。

#### 绑定与发布的时序（结论：配置必须先于发布）

```
create_virtual_goods → Goods(category='A', 文案来自 LLM)
   ↓ 人工确认（流程面板）
configure_auto_delivery(goods_id, rule) → 建 CardGroup / DeliveryRule 绑 goods_id
   ↓ 校验绑定生效，才解锁「上架」
publish_goods_now → item_id 回填
```

理由：`CardGroup.goods_id` 绑的是内部 `Goods.id`，不依赖 `item_id`，所以**没有理由放到发布之后**。反过来若商品已在售而规则未建，期间成交的单会落到 `delivery.py:163-176` 的"查不到商品/规则 → 转人工"分支，**等于静默漏单**——这是品类 A 最贵的一类故障。实现上让 `configure_auto_delivery` 成为面板里「上架」按钮的前置解锁条件，不给人工跳步的机会。

#### 待确认清单必须展示的虚拟商品字段

卡密余量（`remaining_count`）、低库存告警状态（`check_low_stock`）、规则类型（kami/text/image/segments 之一）、交付内容预览。
两条硬规定：**卡密明文只在预览中打码展示，不写入 `product.json`、不写日志**；**库存为 0 或规则未建 → 该行禁止放行**。

#### 定价

虚拟商品**没有 1688 成本价**，§7.1 三级链的第 [1] 级天然不适用 → 一律 `pricing:"manual"`，价格由用户在指令里直给（"29.9"）或在面板手填。**不要为虚拟商品造一个假成本价去喂模型**，那会让护栏区间 `[成本×1.15, ×3.0]` 变成随机数。

### 7.6 `run_risk_scan` 实现说明（v0.5 落地）

落地：`app/ai/risk_scan.py`（纯规则、零 LLM、零 IO）+ `app/ai/decision.py:price_and_copy`（接线与改写循环）。

1. **词表来源全部是 `goofish-risk-guard`，未另发明**（§6 硬性约束 6）。`rules_source` 字段与
   `reference/VERSIONS.txt` 的 `7d6a162c` 一起写进 `product.json`，事后能追溯"当时按哪版规则放的行"。
   自研补充只有三处，且都出自本文：§7.5 一票否决品类、§7.5 禁邮寄话术、§7.4/§6 货源话术与虚构经历。
2. **一处偏离原文档的取舍，需知情**：`forbidden-words.md` 把「绝对化」整类列为 block，但裸词匹配会误杀
   正常实物文案——数据线必然写"超级快充"、日用品有"一次性手套"、"质量保证"是常规表述、"最新款"不是极限词、
   "中央空调"是品类名。故这五个多义表述（`超级 / 一次性 / 保证 / 彻底 / 最新类裸"最"`）降为 **warn**，
   其余照原文 block。同理违禁品只匹配管制形态（`仿真枪/手枪/匕首/管制刀具`），不匹配裸"枪/刀"。
   `白菜价` 按原文注释分面：标题 block、描述 warn。
3. **`not_covered` 自报**：红线 1 降价改标（需 `GoodsEditSnapshot` 历史）、红线 2 类目偏差（需发布第 2 步
   `category_recommend` 返回 catId，红线 2 明说"不要靠猜"）、红线 3 首图 1:1 与图片水印/二维码（需读图/OCR）、
   红线 6 连发同款与红线 9 日发布上限（需账号维度历史）——**扫描器不静默放过自己看不见的东西**，这些项由
   M4 批量放行端点与发布四步各自补校验。
4. **只报不改**：对齐该 skill 自我定位（"不直接替用户改文案，由调用方拿检查结果去改"）。`passed=false` 的
   decision 不可放行（§8.4 节点 4 显红 / 节点 5 置灰）。返回体是 §3.2 `risk_scan` 三键
   （`absolutism_words` / `external_links` / `image_count_ok`）的**超集**——三键留作面板摘要，
   明细在 `blockers` / `warnings`，另有 `delivery_links` 与 `not_covered`。
5. **改写循环在 service 层不在 Skill 层**：定时任务无人值守也要跑到 `decided`（§8.1），所以
   「命中 → 回第 3 步重写 → 重扫，≤2 轮」必须由 `price_and_copy` 自带；违规词回喂进 `draft_copy` 的
   user prompt，并明写"禁止谐音/拆字/加空格绕过"。`NOT_COPY_FIXABLE`（缺图、超长、价格、交付方式）
   不触发重写——重跑文案救不了结构问题，白烧 LLM 调用（手册 §1.7）。
6. **§7.5 两分类落地口径**：虚拟商品 + 已知网盘域名 → `delivery_links`（放行）；虚拟商品 + 域名白名单外
   链接 → block（宁判 NEEDS_MANUAL_CHECK 也不当引流放过）；实物商品任何站外链 → block。三项必写内容
   （交付形式/有效期/退换边界）缺失只 warn + `needs_manual_check: true`，借 `macbook_criteria.txt` 的
   "信息缺失不直接否决"写法。

### 8.4 流程面板（R11）——不是聊天框

**为什么是面板**：上一轮已定 D-2「不自建 agent 运行时」。前端真做一个**对话产品**意味着要给 `ai/provider.py:38` 补 tools、实现多轮循环、会话存储、中断恢复——那是在重造 Qoder/Claude 已有的东西，且与 D-2 直接冲突。而你要的其实是"**看得见流程、能中途干预**"，这件事面板比聊天框做得更好：聊天框里模型说"我跳过定价了哦"你无从查证，面板上第 2 步是灰的还是绿的，一眼就知道。

> **2026-09-20 修正：上面的"面板 vs 聊天框"是个假两难，落地取的是「单轮输入框 + 面板」两者**。自然语言那条路**已经搬进前端**——「1688 采集」页顶部就是一个指令输入框，`POST /api/collect/run` 收 `instruction` 后由**节点⓪ 意图解析**（`ai/intent.py`）抽槽位，缺关键槽位返回 `status=needs_clarification` + 追问文案，前端把追问渲染出来再问一次。
> 这不违背 D-2 的原意：**"不自建 agent 运行时"指的是没有自主规划、没有工具调用协议、没有多轮会话状态机**；轮次由 `for _ in range(MAX_SEARCH_ROUNDS)` 写死（需求设计 D-2026-09-19-15）。所以前端拿到的不是"一个能聊的窗口"，而是"一句人话 → 一次跑完 → 一份结构化结论"，追问也只有一层（缺槽就问，不猜）。
> ~~仍在 Qoder/Claude 会话里说（§6 Skill）~~ 已作废：Skill 目录 2026-09-20 删除，外部 agent 客户端入口**当前不存在**。
> **面板本身仍未做**（见下"后端只需新增两样"，`listing_run_step` 表已在迁移 `0005` 里建好，但 pipeline 不写它、也没有 SSE 事件流）。所以现状是"输入框 ✅ + 结果清单 ✅（`run` 的 `decided[]` 一次返回，同步长请求）+ 逐步实时状态 ❌"。

#### 步骤节点定义

| # | 节点 | 产物 | 失败态处理 | 可跳过 |
|---|---|---|---|:---:|
| 1 | 采集 | `product.json` collect 段 | 解析失败 → 标 `FAILED` + 存 `raw_excerpt`，不阻塞同批其他商品 | ❌ |
| 2 | 定价 | `decision.pricing` + 价格 + 依据 | 无成本价/越界 → 转 `manual`，节点显黄 | ✅（人工直填价） |
| 3 | 文案 | 标题候选 + 描述 | **只由模型产**：不可用 → 留空 + `copy_source=none`（2026-09-20 去掉"回落 `clean_title`"那条兜底），交节点 4 以 `title_missing` 拦下 | ✅（人工改写，`PATCH /api/goods/{id}`） |
| 4 | 风险扫描 | `risk_scan` 结果 | 有违规 → 回第 3 步改写（≤2 轮），仍违规则显红**禁止放行** | ❌ |
| 5 | 待确认 | 清单行 | `pricing:manual` 缺价 / 虚拟品库存 0 → 该行置灰不可勾选 | ❌ |
| 6 | 放行 | `MAPPED` + `goods_id` | 任一件失败整批回滚并逐件报因 | ❌ |
| 7 | 发布 | `item_id` + `receipt.json` | 按 `风控手册 §1.2` 分类：风控/登录态类**不重试**并熔断 | ❌ |

虚拟商品支线在第 6、7 步之间插一个 **6.5 发货配置**节点（§7.5），未完成前第 7 步按钮锁定。

#### 后端只需新增两样

1. **一张步骤台账表** `listing_run_step`：`run_id / goods_id 或 offer_id / step_seq / node / status(pending·running·ok·warn·failed·skipped) / started_at / finished_at / artifact_ref / error_kind / error_msg`。放在 `models/` 下，走 §9-1 同一个新迁移 `0005`。
2. **一个 SSE 事件流**：复用已有的 `api/routes/ws.py` 通道语义，把 `run_id` 的节点状态变更推给前端。**不要新开 WebSocket**——面板是只读观测，SSE 足够且省掉心跳/重连那一套。

每步实现方式：handler 在执行业务函数前后各写一次台账，**面板只读台账，不参与业务逻辑**。因此定时任务、前端按钮（`/api/collect/run`）、老的手动端点（`/api/goods/collect-1688`）驱动同一条流水线，面板显示结果完全一致——这是"多入口不分叉"的关键实现约束。**台账这一层至今没写**：`ListingRunStep` 模型与迁移 `0005` 里的表都在，但 `pipeline.py` 与 `task_runner.py` 都没有任何写入点（全库只有 `models/` 与 `migrations/` 提到它），所以 R11 的实际进度是 0，不是"差个前端"。

#### 可观测硬性要求

- 每步显示**耗时**与关键产物摘要（如"定价 1990 分，依据：成本 350 分 ×5.7，manual=false"）；
- 任一步有**中止**按钮；中止时已完成的节点产物保留（`product.json` 不回滚），下次从断点续跑；
- 面板顶部常显该账号的 **guard 熔断状态**（剩余时间 / 连续失败计数 / 解锁方式），依据 `风控手册 §4 R-9`；
- 失败原因必须给**可读文本 + `error_kind`**（对齐 `protocol.md §1.3` 的错误分层），不能只给堆栈。

#### 明确不做

对话历史与自由文本输入框（避免看起来像聊天框）；面板内嵌 LLM 自主循环；步骤级的"让模型自己决定跳过哪步"。

**D-2026-09-18-2｜自然语言入口 = MCP server + Skill，不自建 agent 运行时**
理由：`ai/provider.py:38` 只支持纯文本 chat，自建 agent 要先补 tools/多轮/中断确认，是在重造 Qoder/Claude 已做好的部分。
已接受代价：交付物不能脱离 agent 客户端单独作为网页产品（日后产品化，把 MCP server 直接挂前端对话框即可）。

> 本条的核心理由（"自建 agent 是在重造已有能力"）**没有被推翻，只是重新划了界**：自研的是**固定五节点 + 写死轮数的编排**（需求设计 D-2026-09-19-15），不是通用 agent 运行时——没有工具调用协议、没有自主规划、没有中断确认循环，"停"由"代码里根本没有 approve/publish 那条调用"保证。真正被证伪的是"要跑自然语言链路就必须有 agent 客户端"这个隐含前提。
> 代价换了方向：脱离客户端不再是代价，反而是需求本身（不开 Qoder 也要能铺货 + 要能无人值守定时跑）；新增的代价是**Skill 里的人工纪律必须逐条翻译成代码校验与测试**，映射表见需求设计 §8。

**D-2026-09-18-3｜定价 = 成本价驱动 LLM + 规则兜底 + 人工终局（用户决定）**
理由：1688 成本价是**唯一稳定可得**的价格输入（`parser.py:extract_price_cent` 已解析），竞品价三个候选都没落地；先让链路跑通，竞品价作为增强项后置。
明确限制：成本价只能定下限，故 `confidence` 上限锁 `medium`，`pricing:"manual"` 必标红。
否决：v0.1 的"竞品价锚定"（阻塞在 §13-Q1，会导致 M2 无法开工）。

理由：用户诉求是"看得见流程、能中途干预"，面板（步骤台账 + SSE）比聊天框更直接地满足，且可审计——模型说"我跳过了定价"在面板上无处遁形。更重要的是它**不推翻 D-2**：真聊天框必须给 `ai/provider.py:38` 补 tools 并自建多轮循环，与"不自建 agent 运行时"正面冲突。

连带结论：虚拟商品无 1688 成本价，一律 `pricing:"manual"`，禁止造假成本喂模型。

**D-2026-09-19-8｜`ai-goofish-monitor` 只迁移操作纪律，不迁移反检测技术**
理由：核实后它是**纯只读监控项目**——零写操作、零 1688 逻辑，且 mtop 请求由真实浏览器页面自发、它只被动捕获（`scraper.py:355-390`）。我们走 HTTP 直连自算签名，它的 JS 注入 / Chrome 启动参数 / context 指纹**全部无对应物可用**。
可迁移的部分（熔断参数、失败分类禁重试、节奏基线、保守并发、拉黑+TTL、幂等键、规则优先于 LLM、参数取真实快照）已抽进 `docs/闲鱼风控操作手册.md §1`，共 8 条。
关键取舍：所有风控约束**落在代码层闸门**（工具返回 `retryable:false`、不暴露 force 参数），不写进提示词。提示词可被越狱和幻觉，代码层不行——这直接回应了"避免 LLM 操作时报错"的原始诉求。

**D-2026-09-19-9｜人工放行闸门的位置：采集工作区，不在商品页多选；图片端点不鉴权（v0.6）**
