# xianyu-core 前端页面任务文档

> 版本：v1.4（2026-09-20）
> 说明：前端薄面板的任务清单与进度标记，配合 `后端接口文档.md` 使用（接口 ↔ 页面对照见其 §9）。
> v1.0 那一轮是**布局重构**（单页 Tab → vue-router 多页面 + 菜单壳）；v1.1 这一轮补的是**采集链路页面**（§7.6/§8.1 的人工闸门落地）与全站逐页冒烟；v1.2 补的是**自然语言采集入口**（`采集链路硬化…需求设计.md` 的 S4：一句话 / 检索后勾选 / 定时面板）；v1.3 只动**报错可见性与反代超时**（页面清单零变化）：`nginx.conf` 的 `location /api/` 补 `proxy_read_timeout/send_timeout 900s`（原先不写 = 默认只等 60s，配模型后 `/api/collect/run` 必然 504，**而那一轮其实跑完了**）、`api/index.js` 不再把网关的整页 HTML 拼进报错、采集失败提示附"超时先去工作区刷待确认清单"。另记一条使用注意：**采集那一轮在跑时别同时抢着扫码**（同一容器抢外网，闲鱼扫码因此 502 过一次）。v1.4 只动**「文案为什么是空的」这件事怎么说出口**（后端同轮把成品文案的兜底改成"只出自模型"，见接口文档 v1.8）：工作区待确认清单加「0 件可放行：<逐条原因>」横幅（原先只是复选框置灰 + 按钮禁用，用户点不动只能猜）、风险列加「文案空白」标签、单件详情新增「文案来源」行（`llm`/`human`/`none`/历史行的 `clean-title`，`none` 时把 `copy_error` 原样摊开）、重跑后的提示语带上文案状态；采集页「拟用标题」为空时显示「文案未产出…去工作区重跑」而不是留一格空白。页面清单零变化。
